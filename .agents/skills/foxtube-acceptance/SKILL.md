# Приёмка FoxTube

Прочитай [TestTask.md](../../../TestTask.md), [testing.md](../../../docs/testing.md)
и [status.md](../../../docs/status.md). Выбери связанные A1–A9; для небольшой функции не нужен полный релизный прогон.

1. Установи фактическую готовность окружения и существующие команды. Если каркаса нет, проверяй только обвязку; не создавай фиктивные прикладные результаты.
2. Запускай проверки на отдельных данных/томах. Используй настоящий PostgreSQL; для медиа — настоящий FFmpeg и Nginx. Не изменяй код приложения ради зелёного теста.
3. Основной сценарий: новая регистрация → новый файл → очередь/READY → плеер с движущимся currentTime и перемоткой → сохранённые лайк и комментарий.
4. Матрица приватности: отдельные аккаунты, метаданные/превью/MP4/HEAD/Range, отзыв и скрытие. Учитывай, что открытая передача может завершиться.
5. Для UI проверь 1440×900 и 390×844, пустые/ошибочные состояния. Для H.264 используй Playwright с Chrome в тестовом окружении; отсутствие кодека не скрывай skip.
6. Для worker проверь остановку/повтор и сохранение private/hidden/deleted. Для поставки — чистую Ubuntu из архива, повторный seed/bootstrap и сохранность после рестарта.
7. Для каждого сценария верни команду, окружение, passed/failed/blocked и доказательство. Дефект — с минимальным воспроизведением. Артефакты без секретов сохраняй в .artifacts.

Тяжёлые браузерные и нагрузочные прогоны не запускай параллельно. Отделяй
недоступное окружение от дефекта приложения. Статический анализ и успешная
проверка конфигурации не заменяют воспроизведение видео и установку Ubuntu.
