# Видеоконвейер FoxTube

Прочитай [архитектуру](../../../docs/architecture.md) и
[защиту медиа](../../../docs/security.md). Лимиты и форматы берутся оттуда.

Проследи затронутый путь: браузер → Nginx → API → исходник/БД → worker →
публикация → ACL → Nginx → плеер. Определи, что остаётся на диске/в БД при сбое на каждой изменяемой границе.

- Загрузка: авторизация/CSRF/резерв до тела; ограниченные блоки, реальные байты, разрыв соединения и освобождение резерва. Не допусти буферизации целого файла прокси или приложением.
- Очередь: короткий claim, SKIP LOCKED, heartbeat/lease и token попытки. Долгий subprocess без открытой транзакции; повторы не публикуют чужой результат.
- FFmpeg: фактический контейнер/потоки, тайм-аут probe, поворот/размеры/беззвучный файл, MP4 H.264/AAC faststart. subprocess без shell, сети и секретов; вывод не заполняет pipe или диск.
- Публикация: проверить закрытые выходные файлы, атомарно переименовать, затем READY только текущей попыткой. Состояния private/hidden/deleted сохраняются.
- Выдача: разрешение на каждый GET/HEAD/Range, internal location, правильные 206/416 и перемотка. Исходник не становится публичным.
- Восстановление: остановка FFmpeg/worker, истёкшая аренда, потеря БД, отмена загрузки и нехватка места. Остатки очищаются без удаления активного результата.

Проверяй настоящим коротким видео через Nginx, а не только прямым вызовом функции.
Для воспроизведения используй Chrome с H.264 в тестовом окружении.
Отдели прогресс отправки от обработки. Верни команды, параметры результата,
проверенные аварийные сценарии и недоступные проверки. Открытую передачу MP4 не обещай отозвать.
