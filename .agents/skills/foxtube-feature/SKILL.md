# Вертикальная функция FoxTube

Прочитай [AGENTS.md](../../../AGENTS.md), [архитектуру](../../../docs/architecture.md)
и [состояние](../../../docs/status.md). Исследуй существующую реализацию до выбора файлов.

1. Назови действие пользователя и наблюдаемый результат по TestTask.md. Определи затронутые роли, API/страницу и критерий проверки.
2. Переиспользуй общий сервис и ACL. Если меняется схема — добавь миграцию и ограничения PostgreSQL; публичный контракт меняй вместе с вызывающим UI.
3. Реализуй минимальную законченную вертикаль, включая ошибку, пустое состояние и запрет чужого объекта. Не добавляй соседние возможности и новую инфраструктуру.
4. Для списка проверь фильтрацию доступа до пагинации, пакетные агрегаты и отсутствие N+1. Для мутации — владельца, CSRF и транзакционность.
5. Для экрана сохрани компоновку YouTube, русский текст и мобильный размер. Интерактивность — обычный JavaScript; пользовательский текст не вставляй через innerHTML.
6. Выполни подходящую проверку из [testing.md](../../../docs/testing.md). Регрессионный тест должен воспроизводить исходный дефект, а не устройство функции.
7. Верни изменение поведения, команды/результаты и ограничения. Главному агенту передай сведения для обновления status.md.

Делегирование не обязательно: при работе внутри дочернего агента выполняй поручение сам.
Не считай API 200 доказательством работающего пользовательского сценария.
