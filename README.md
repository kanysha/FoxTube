# FoxTube

Видеоплатформа по [TestTask.md](TestTask.md): Python 3.12, FastAPI, PostgreSQL 17,
Jinja2 и простой JavaScript. Четыре сервиса: Nginx, API, PostgreSQL и worker.

Публичный репозиторий: [kanysha/FoxTube](https://github.com/kanysha/FoxTube).

Работают регистрация, загрузка с прогрессом, очередь PostgreSQL, обработка FFmpeg,
просмотр с перемоткой, каналы, поиск и студия. Лайки, комментарии, подписки и
плейлисты сохраняются в БД. Приватные видео доступны владельцу и выбранным
пользователям. Есть жалобы, скрытие/восстановление видео, управление ролями и
журнал модерации. Демо создаёт настоящие MP4 через штатный конвейер.

Основные пользовательские процессы повторно проверены:
[отчёт процессов](docs/review-workflows-2026-11-04.md).
Установка одной командой на чистой Ubuntu 22.04.5 проверена отдельно:
[отчёт Ubuntu](docs/review-ubuntu-2026-11-04.md). Нагрузочная приёмка на 4 CPU/8 ГБ
остаётся. Факты — в [текущем состоянии](docs/status.md),
оставшиеся проверки — в [roadmap](docs/roadmap.md).

## Запуск

На чистой Ubuntu 22.04 или 24.04 LTS из каталога распакованного проекта:

```bash
sudo bash scripts/bootstrap.sh
```

С демо-наполнением: `sudo bash scripts/bootstrap.sh --demo`. Для уже запущенного
проекта: `bash scripts/demo.sh`. Будут созданы 6 аккаунтов, 12 обработанных роликов,
комментарии, плейлисты, подписки и жалоба. Пароли случайные, сохраняются только в
`secrets/demo/manifest.json` с правами 0600; повторный запуск использует те же данные.

Установка без заранее установленного Docker подтверждена на Ubuntu 22.04.5 LTS
(4 vCPU/8 ГБ). После установки проверены настоящий Chrome, приватное видео,
повторный bootstrap и перезагрузка ВМ. Ubuntu 24.04 отдельно не проверялась.

Если Docker Engine/Desktop и Compose уже работают на macOS или другом Linux:

```bash
bash scripts/bootstrap.sh
```

На Ubuntu и при повторе используйте `sudo bash scripts/bootstrap.sh`;
для ручной настройки сети — `bash scripts/bootstrap.sh --no-lan`.

Скрипт создаёт приватный .env со случайными паролями, собирает приложение,
применяет миграции и ждёт готовности сервисов. На Ubuntu через sudo автоматически
выбирается частный IPv4 основного интерфейса: сайт открывается из его подсети по
адресу `http://IP:8080`, который выводится в конце. Публикуется только Nginx;
PostgreSQL и API остаются внутри Docker. Фильтр сохраняется после перезагрузки,
SSH и настройки UFW не меняются. Повтор сохраняет пароли и данные.

Для нескольких интерфейсов: `sudo bash scripts/bootstrap.sh --lan-ip 192.168.1.16`.
`--no-lan` пропускает управление сетью и сохраняет существующие настройки/правила.
Подробности — [локальная сеть и firewall](docs/development.md#локальная-сеть-и-firewall).
Проверка на чистой Ubuntu 22.04, повтор и reboot — [отчёт LAN](docs/review-lan-2026-11-05.md).
На macOS по умолчанию доступны [интерфейс](http://localhost:8080),
[Swagger /docs](http://localhost:8080/docs) и [readiness](http://localhost:8080/health/ready).

Требуются интернет для первой сборки, 4 CPU, 8 ГБ RAM, 40 ГБ свободного места;
Compose 2.20+. На Ubuntu скрипт при необходимости установит системные Python 3 и
nftables для настройки сети. FFmpeg/Node.js на хосте устанавливать не нужно.

## Учётная запись

Откройте [регистрацию](http://localhost:8080/register), укажите имя, email и пароль
длиной 12–128 символов. После регистрации откроется аккаунт с адресом канала.
Вход доступен на [/login](http://localhost:8080/login), выход — в верхней панели.

Используйте адрес, напечатанный bootstrap: на Ubuntu это выбранный локальный IP,
на macOS по умолчанию http://localhost:8080.
Защита изменяющих запросов проверяет точное совпадение с FOXTUBE_PUBLIC_ORIGIN;
открытие через 127.0.0.1 при origin localhost не позволит отправить форму.
Swagger использует ту же сессию: Try it out автоматически получает CSRF-токен.
Подробности API — в [инструкции разработки](docs/development.md#учётные-записи-и-api).

## Видео

После входа откройте [/upload](http://localhost:8080/upload), выберите MP4/MOV/WebM,
название и доступ. По умолчанию видео приватное. После отправки дождитесь обработки
и нажмите «Смотреть видео». Свои загрузки и настройки доступны в
[/studio](http://localhost:8080/studio); на странице видео можно изменить метаданные,
выдать доступ по точному email зарегистрированного пользователя или удалить видео.

Вход: до 500 МиБ, 20 минут, 1080p и 60 fps. Результат: MP4 H.264 до 720p со
звуком AAC при его наличии и JPEG-превью. Плеер FoxTube поддерживает паузу,
перемотку, громкость и полный экран; без JavaScript остаются элементы браузера.
В центре плеера — исходный логотип сайта без дополнительных элементов.
Карточки используют миниатюры 16:9, длительность и аватар канала рядом с названием.
При наведении первые 20% ролика повторяются без звука, со значком mute
и полосой позиции предпросмотра. На touch
касание открывает видео; экономия трафика и сокращение движения отключают предпросмотр.
Индикаторы сопровождают отправку, обработку и ожидание данных.
Для отправки следующего файла нужно завершить или удалить текущий
черновик. Квота — 5 ГиБ на пользователя, включая исходники и резервы обработки.

На странице просмотра можно поставить лайк, написать комментарий, сохранить видео
в свой плейлист или отправить жалобу. Подписка находится на странице канала;
[/subscriptions](http://localhost:8080/subscriptions) показывает доступные видео
подписок. Плейлисты автора видны в канале; свои — в
[/playlists](http://localhost:8080/playlists). Публичный плейлист сохраняет права
каждого ролика: приватные, скрытые и удалённые элементы не раскрываются зрителю.

## Модерация и роли

Первого администратора назначают существующему аккаунту через одноразовую команду
с привилегиями миграции:

```bash
docker compose run --rm --no-deps migrate python -m app.moderation.bootstrap --email your-existing-account@example.com
```

Далее [/admin](http://localhost:8080/admin) позволяет найти пользователя по точному
email/ID и изменить роль с обязательной причиной. Последнего администратора понизить
нельзя. Модератор и администратор используют [/moderation](http://localhost:8080/moderation)
для жалоб, скрытия, восстановления и закрытия обращений. Эти роли не открывают
приватные видео. Стандартного пароля администратора и публичного bootstrap API нет.

## Работа с проектом

```bash
make up           # сборка, миграции, запуск
make ps           # состояние
make logs         # журналы приложения
make down         # остановка с сохранением томов
make check        # линтеры, типы, unit-тесты в Docker
make test         # интеграционные тесты в отдельном окружении
make test-browser # Chrome: видео, приватный доступ, Swagger и модерация
make test-resilience # аварии worker/БД, удаление при FFmpeg, рестарт
make test-capacity # 500 МиБ, память API, две загрузки и десять HTTP-зрителей
make agents-check
make doctor
```

Две последние команды проверяют агентную обвязку и требуют только Python 3.11+.
Зависимости приложения фиксируются в uv.lock; runtime-образ не содержит dev-пакеты.
Не удаляйте .env при сохранённом томе PostgreSQL: новые пароли не обновят роли
в существующей базе. `docker compose down` сохраняет данные; `down --volumes` удаляет их.
