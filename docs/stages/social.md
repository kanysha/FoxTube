# Этап: взаимодействия и плейлисты

Дата проверки: 2026-11-04. Модуль `app/social`, миграция `0004_social` после
`0003_video_pipeline`. Новых сервисов и зависимостей нет.

## Реализовано

- Лайк/снятие лайка и счётчики: PostgreSQL, уникальная пара пользователь–видео,
  идемпотентные PUT/DELETE, без дубликатов при параллельных запросах.
- Комментарии: создание, постраничное чтение, удаление автором или владельцем
  видео; имя и ссылка на канал автора. Email в ответах отсутствует.
- Подписка/отписка, количество подписчиков, собственный список подписок и лента
  доступных видео. Подписка на себя отклоняется.
- Публичные и приватные плейлисты: создание, частичное изменение, удаление,
  добавление и удаление видео. Управляет только владелец плейлиста.
- Рабочие элементы на странице просмотра, страницы `/playlists`,
  `/playlists/{id}`, `/subscriptions`, JSON API и Swagger-схемы.
- Тексты проходят проверку длины и недопустимых Unicode-символов. HTML
  экранируется Jinja; комментарии в JavaScript вставляются через `textContent`.

## Границы доступа и нагрузки

Правила видео повторно используются из `app.videos.service.readable`: статус
READY, модерация, удаление, приватность и персональный доступ. Публичность
плейлиста не даёт права на его приватные видео. Названия, UUID и количество
недоступных видео не включаются в ответы плейлистов и ленты; ACL применяется
до подсчёта и пагинации. Приватный плейлист для чужого посетителя возвращает
одинаковую 404 с отсутствующим.

Записи требуют сессии, CSRF и допустимого Origin. Владелец выводится из сессии,
входные схемы запрещают лишние поля. Мутации видео удерживают блокировку строки
видео и проверяют ACL отдельным запросом после получения блокировки. Это
закрывает ситуацию, когда запрос ожидал блокировку во время отзыва персонального
доступа. Удаление чужого/недоступного/отсутствующего комментария имеет общую 404.

Ограничения: 100 плейлистов на пользователя, 500 видео в плейлисте,
1000 подписок, 10000 комментариев у видео. Максимум 2000 символов комментария
и описания, 200 символов названия плейлиста. Страница содержит до 50 записей.
Лимиты количества сериализуются блокировкой владельца, плейлиста или видео.
Лимиты частоты сохраняются в PostgreSQL отдельно на пользователя и IP, окно
15 минут: лайки 600, комментарии 30, удаления комментариев 120, подписки 120,
операции плейлистов 120, операции с их элементами 240; лимит IP в пять раз выше.
Для счётчиков плейлистов используется групповой запрос в пределах владельца,
без отдельных запросов для каждой карточки. Нагрузочный тест не проводился.

Миграция задаёт внешние ключи с каскадным удалением, уникальность пар,
ограничения содержимого и индексы. API получает только необходимые права на
новые таблицы; worker не получает доступа к ним.

## Выполненные проверки

- Ruff, проверка форматирования, mypy, ShellCheck: прошли в development-образе.
- Unit-тесты проекта: 32 passed.
- `node --check app/web/static/social.js` и `git diff --check`: прошли.
- `bash scripts/test.sh tests/test_social_integration.py
  tests/test_integration.py::test_migrations_round_trip_in_separate_database`:
  12 passed (11 social и один миграционный roundtrip), 17.30 с тестового запуска.
  Сборка использовала `uv sync --frozen`; Compose, PostgreSQL, Nginx и FFmpeg
  настоящие. Окружение и его тома удаляются после проверки.
- Интеграционные сценарии включают загрузку и обработку двух видеозаписей,
  сохранение социальных действий, параллельные лайки/подписки, удаление
  комментариев по правам, единые 404, изменение приватности и отзыв доступа,
  ожидание блокировки с отзывом grant, запрет hidden/deleted/processing видео,
  пагинацию после ACL, XSS-экранирование, CSRF/Origin, запрет подмены владельца,
  NUL/непарный Unicode-суррогат и лимит частоты.
- Независимое статическое ревью безопасности: новых открытых подтверждённых
  нарушений доступа не найдено. Ревьюер самостоятельно тесты не запускал.

Первый интеграционный запуск дал 10 passed и одну ошибку тестового клиента:
httpx не смог сериализовать непарный суррогат до отправки запроса. Тест исправлен
на передачу escaped JSON; повторный запуск полностью прошёл. Существующее
предупреждение FastAPI/Starlette об использовании httpx в TestClient остаётся.

## Интеграция и оставшиеся проверки

Контракт страницы канала: `data-channel-subscription="UUID"` активирует
виджет подписки; `service.channel_playlists(...)` возвращает `PlaylistPage`.
Макрос `playlist_cards(items)` находится в `social_parts.html`. При передаче
`model_dump` в Jinja списки читаются через `['items']`.

Общий лимит тела JSON API, итоговая интеграция страницы канала, браузерная
проверка кликов и полного медиасценария выполняются при объединении этапов.
В этой ветке браузер и установка на чистой Ubuntu VM не проверялись. Отчёт
выше не заменяет итоговую проверку собранной платформы.

Перестановка элементов, автовоспроизведение плейлиста и редактирование
комментариев не входят в этот этап. Плеер PLAYER-01 остаётся отдельной задачей
после основного roadmap.
