Область: смена/восстановление пароля, свои активные сеансы, HTTPS, cookies,

## Реализовано

- `/account`: смена пароля с проверкой текущего, новая cookie/CSRF, отзыв
  остальных сеансов и ссылок; список собственных активных входов по 20,
  выборочное завершение и завершение остальных. Текущий вход сохраняется
  при отзыве остальных; для его завершения используется выход.
- Одноразовая ссылка на 30 минут, SHA-256 в PostgreSQL, запрет повторного
  использования, отмена предыдущей ссылки при новом запросе. Reset отзывает
  все входы без автоматического логина. Проверка старого хеша при login
  предотвращает поздний вход старым паролем. Операции сериализуются по аккаунту.
- Одинаковый ответ для существующего/неизвестного email, ограничения частоты,
  TLS SMTP с проверкой сертификата, два фоновых слота на процесс без соединения
  БД во время отправки. Без SMTP всем возвращается понятный 503.
  Фрагмент ссылки удаляется из адреса и хранится только в памяти страницы;
  Referrer-Policy для восстановления — no-referrer.
- Production требует HTTPS. Отдельный Compose overlay оставляет четыре
  сервиса и публикует только TLS Nginx, сертификаты read-only; TLS1.2/1.3,
  HSTS180 дней, Secure/HttpOnly/SameSite cookie, точный Origin/CSRF.
  Uvicorn не доверяет proxy headers, Nginx очищает их. Схема перенаправлений
  берётся из настроенного origin, включая 307 с сохранением тела запроса.
- Успешная публичная статика кешируется пять минут, ETag/304 сохраняются.
  HTML/API/сессии/ошибки и приватные MP4/превью не получают публичного кеша.
  Проверка доступа для новых HEAD/Range сохраняется.
- Обновлены совместимые версии в `uv.lock`; инструменты разработки остаются
  вне runtime. Миграция `0006_account_security` задаёт ограничения токенов
  и минимальные права API/worker. Документы запуска и настройки обновлены.

## Ограничения и следующий шаг

Реальная доставка SMTP отложена: до включения проверить сервис, отправителя
и доставку по публичному HTTPS origin. Фоновая отправка best effort без
долговечной очереди и автоматического повтора; при сбое запрос повторяют.
Успешный reset проверяется интеграционно, Chrome использует отключённый SMTP.

Публичный сертификат, его продление, внешний прокси/firewall и развёртывание
на Ubuntu в этом этапе не проверялись. TLS smoke использует временный CA и
API без БД; Chrome/SQL проходят отдельно. Capacity и аварийная приёмка заново
не запускались. pip-audit не охватывает все системные компоненты образов.
Следующий шаг — настроить SMTP и сертификат на целевом окружении, применить
миграцию с TLS overlay и проверить конечный адрес; это не публикация проекта.
