# Миниплеер 2026-11-10

Ветка `codex/miniplayer-2026-11-10`. Пользовательское расширение PLAYER-01,
связанное с A1/A2/A4. Основа — существующий HTML5-плеер и защищённый MP4.

## Поведение

Кнопка в основном плеере переносит тот же элемент video в окно справа внизу.
При переходах по внутренним страницам воспроизведение продолжается: сохраняются
декодер, позиция, пауза, громкость, mute, скорость, повтор и локальные WebVTT.
Заголовок и кнопка разворачивания возвращают видео на страницу просмотра;
закрытие останавливает медиа, очищает источники, дорожки и локальные Blob.

У карточек с доступным видео есть отдельная кнопка миниплеера. Она закрепляет
уже играющий hover-предпросмотр с его текущей позиции; ограниченный цикл
предпросмотра снимается. На сенсорном экране кнопка видна постоянно и запускает
тот же сценарий без hover. Обычный автоматический предпросмотр остаётся без
звука и учитывает reduced motion/Save-Data. Закрепление — явное действие.

Миниплеер даёт паузу, перемотку, громкость/mute, субтитры, настройки и fullscreen.
Для беззвучного видео предусмотрена отдельная кнопка «Включить звук».
Если браузер запрещает play со звуком, выполняется попытка без звука;
если запрещена и она, доступно явное нажатие воспроизведения. Переключение
режимов не присваивает src и не вызывает load. При поддержке moveBefore
используется атомарное перемещение, иначе тот же video переносится с
возобновлением при необходимости.

На узких экранах окно занимает доступную ширину с отступами safe area;
кнопки имеют сенсорный размер, настройки прокручиваются при малой высоте.
Нижний отступ страницы позволяет добраться до перекрытых окном элементов.
Меню и шапка располагаются выше миниплеера. Крупная центральная кнопка в маленьком
окне скрыта, чтобы не перекрывать субтитры; воспроизведением управляет панель.
В один момент играет один ролик;
открытие другого видео завершает прежнее.

Для непрерывного просмотра разрешённые внутренние GET-переходы получают
настоящий Jinja HTML с сервера, обновляют основную область и навигацию,
сохраняя контейнер video. Работают поиск, back/forward и возврат к ролику.
Скрипты из нового HTML не исполняются; модули имеют отмену запросов/таймеров
и повторную инициализацию. Задержавшийся ответ не заменяет более новую страницу.
Вход/выход, внешние ссылки, перезагрузка, новые вкладки и уход с занятой или
изменённой формы используют обычную навигацию. Непрерывность между отдельными
HTML-документами не обещается.

## Безопасность и проверки

Независимое read-only security-ревью не выявило открытых подтверждённых P0–P3
в изменённой области. Найденный P2 инициализации форм модерации после внутреннего
перехода исправлен общим lifecycle. Проверены ограничения origin/конечного
redirect, допустимые маршруты, версия оболочки, UUID зрителя и удаление script.
CSRF обновляется из серверного HTML, правила Origin/CSRF/ACL не ослаблены.

Доступ проверяется при навигации, фокусе/возврате видимости и периодически
для открытого миниплеера. Смена аккаунта в другой вкладке передаёт только
сигнал через BroadcastChannel; получатель заново запрашивает серверную сессию.
Ни токены, ни данные пользователя через канал не передаются. Метаданных 200
недостаточно: требуется совпадение UUID и доступный защищённый playback_url.
У владельца скрытого видео metadata 200 с playback_url=null также закрывает
миниплеер. Ошибка сети ставит видео на паузу. GET/HEAD/Range остаются под
серверным ACL; уже полученные байты не отзываются.

Дополнительный просмотр runtime-снимка выявил ложное сообщение ошибки при
закреплении без предварительного hover: только созданный video ещё не выбрал
источник, но начальный NETWORK_NO_SOURCE принимался за окончательный отказ.
Исключение ограничено новым перенесённым предпросмотром с пустым currentSrc;
реальные ошибки и уже завершившийся до deferred JS отказ обычного source
по-прежнему обрабатываются. Добавлены прямые keyboard/touch pin-регрессии:
реальное воспроизведение и скрытое сообщение об ошибке.

`make check`: **294 unit passed**, Ruff/format/mypy/ShellCheck passed.
`make test`: **98 integration passed**, настоящий PostgreSQL/Nginx/FFmpeg.
`make agents-check`, синтаксис изменённых JS и `git diff --check`: passed.
Полный `make test-browser`: **passed**, Google Chrome **156.0.8078.80**,
настоящие H.264/AAC, FFmpeg, PostgreSQL и Nginx; ошибок JavaScript нет.
Прошли основной/расширенный плеер, реальный 404 и fallback source, hover и
reduced motion/Save-Data, миниплеер, социальные действия, административные формы,
модерация, приватность/отзыв доступа, Swagger и lifecycle пользовательских процессов.

Миниплеер проверен при внутренних переходах, поиске, back/forward и возврате
к основному плееру, во время воспроизведения и паузы. Проверены громкость,
mute, ручное включение звука, скорость, локальные WebVTT, освобождение медиа,
закрепление уже играющего предпросмотра и прямой запуск без hover клавиатурой
и касанием. Mobile/touch: 320×740, 390×844 и 844×390, включая настройки.
Задержанные ответы навигации не перезаписывают более новую страницу.
Отдельно пройдены обычная навигация при входе, выход из другой вкладки,
отзыв приватного доступа и скрытое видео владельца с metadata 200/null.
В последнем сценарии используется настоящий внутренний переход и проверка HTTP;
`bring_to_front` в headless Chrome сам по себе не доказывает событие focus.

Регрессии проверяют идентичность video и document, неизменный currentSrc и
отсутствие loadstart во время переключений. Закрытие проверяется по pause,
отсоединению элемента, удалению src/poster/source/track, пустому буферу,
HAVE_NOTHING/NETWORK_EMPTY и отсутствию продвижения времени. Chrome может
оставлять историческую строку в read-only currentSrc после освобождения
ресурса; требовать пустую строку ошибочно. Это поведение описано в
[WHATWG issue 10410](https://github.com/whatwg/html/issues/10410) и следует
проверять вместе с [алгоритмом выбора ресурса](https://html.spec.whatwg.org/multipage/media.html#concept-media-load-resource).

## Применение и работающие экземпляры

Установлен образ `foxtube-app:mini-20261110-r1`. Перед заменой проверены SHA-256
всех файлов app, pyproject.toml и uv.lock в подготовленном образе. Заменены только
API/worker; четыре сервиса healthy. PostgreSQL/Nginx не пересозданы, тома и
миграции сохранены; Nginx прошёл проверку конфигурации и reload.

Закрытые резервные копии конфигурации/состояния: локально

`/root/foxtube-miniplayer-backup-20261110-r1`; предыдущий образ сохранён для отката.
Секреты и содержимое .env в отчёт/артефакты не включены.

Chrome на обоих работающих экземплярах проверил совпадение всех JS/CSS с
исходниками, реальное play/seek/resume, медленный двойной клик, перенос того же
video с позицией/паузой/громкостью/скоростью/WebVTT, внутреннюю навигацию,
возврат, ручное включение звука и закрытие с освобождением ресурса.
Карточка на главной запускается без предварительного hover, затем сохраняет
video при переходе к поиску; проверены узкий экран и настройки. Снимки просмотрены:
субтитры видны без центральной кнопки, закрытое боковое меню не перекрывает окно.
Ошибок JavaScript нет. Использовались существующие публичные видео; аккаунты и
реальные данные не создавались/не изменялись. Проверки некорректного входа (401)
и регистрации (422) достигли проверки данных вместо ошибки CSRF. Переход
с 127.0.0.1 на настроенный localhost сохранён.

SSH root и веб-порт сервера доступны. На сервере сохранён bind `0.0.0.0:8080`;
TCP 5432/8000 извне закрыты. Новых сетевых изменений для миниплеера нет.

## Границы

Браузерная проверка использует настоящий Google Chrome и его mobile/touch
эмуляцию. Физические iOS/Android и Safari/Firefox этим этапом не проверены.
Новые сервисы, SPA, HLS, миграции и изменения сетевой политики не добавлялись.
