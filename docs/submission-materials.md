# Материалы для сдачи

После проверок и коммита исходников из корня проекта сначала захватите состав:

```bash
python3 scripts/build-submission.py --stage-only /absolute/path/FoxTube-stage
```

Затем проверьте staging на секреты, включая доступные диалоги, доказательства,
конфигурацию Git и распакованные Git-объекты. После успешной проверки создайте ZIP:

```bash
python3 scripts/build-submission.py --pack-stage /absolute/path/FoxTube-stage \
  --output /absolute/path/FoxTube-submission.zip
```

Второй этап читает только зафиксированный staging, проверяя manifest; он не
перечитывает дописываемые диалоги и исходники. Не меняйте staging после проверки.
Нужны Python 3.11+ и Git; зависимости приложения не устанавливаются. Существующий
ZIP заменяется только с `--force`. Состав воспроизводится по явным спискам;
время захвата и растущие оригинальные диалоги меняют итоговый SHA-256.

Скрипт требует чистые tracked-файлы, берёт исходники через Git index и сохраняет
`.git`, включая объекты, refs, reflogs и ветки. Исключаются регистрации внешних
worktree, lock-файлы и служебные `COMMIT_EDITMSG`/`FETCH_HEAD`. Незакоммиченные
новые файлы не входят. Исходники, документация, тесты, демо и конфигурация
развёртывания должны быть заранее добавлены в Git.

В `submission/` добавляются выбранные протоколы и снимки успешных проверок,
оригинальные JSONL бесед, их manifest, доступная внешняя агентная обвязка,
явно обозначенная безопасная выборка глобальных настроек и список недостающего.
Источником учёта служит `.artifacts/final-audit/materials-inventory.json`.
Готовые JSONL копируются целыми исходными байтами; скрипт не вырезает строки,
не исправляет содержимое и не восстанавливает диалоги из SQLite. Текущие беседы
отмечаются `incomplete`: будущие сообщения в уже собранный архив не попадут.

По инвентаризации доступны 18 оригиналов, отсутствуют 30. Точные ID и исходные
пути записываются в `submission/MISSING-MATERIALS.md`. Недостающие оригиналы
нужно получить из среды создания или подлинного экспорта владельца. Общие базы
Codex содержат посторонние проекты и в архив не входят. Исторические версии
глобальных настроек, внутренние реализации MCP и состояние подключений
приложения недоступны как переносимые проектные материалы и не имитируются.

`.env`, реальные загрузки, demo manifest с паролями, ключи, auth-файлы, зависимости,
временные каталоги и общие базы не включаются. Глобальный config целиком не
копируется; производный JSON содержит только выбранные настройки модели,
имена/включённость MCP и имена переменных окружения, без их значений и адресов.
Наличие литералов синтетических паролей в автотестах не означает наличие
полномочных паролей работающих установок.

**Упаковщик не заменяет проверку секретов.** После захвата текущих диалогов нужно
отдельно просканировать весь staging, исходники и Git-объекты, проверить
подозрительные совпадения и только затем запускать `--pack-stage`. Если оригинал содержит
секрет, его нельзя незаметно отредактировать и выдать за подлинник: вопрос
включения такого оригинала решается отдельно с владельцем.

Для каждого файла, кроме самого manifest, сохраняются SHA-256, размер и права.
Упаковщик проверяет CRC ZIP, распаковывает его в новый временный каталог, сверяет
manifest, запускает `git fsck --full`, проверяет refs, число Git-объектов и отсутствие изменений
tracked-файлов. Допустимы только дополнительные untracked-материалы `submission/`.
Рядом с ZIP создаются `.report.json` с результатами и `.zip.sha256`.
