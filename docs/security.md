# Безопасность и границы доступа

Применять к реализации и ревью. Реализованы учётные записи, загрузка, ACL,
обработка видео, социальные действия, модерация, роли и аудит. Результаты
проверок и границы независимого ревью — в [status.md](status.md).

## Матрица просмотра

| Состояние видео | Гость/посторонний | Владелец | Пользователь с разрешением | Moderator/admin без разрешения |
|---|---|---|---|---|
| READY, публичное, видимое | Да | Да | Да | Да |
| READY, приватное, видимое | Нет | Да | Да | Нет |
| Не готово, скрыто или удалено | Нет | Нет в плеере | Нет | Нет |

Владелец видит статус своей загрузки. Модератор видит служебную карточку жалобы
и может скрыть/восстановить видео; это не даёт доступа к приватным байтам.
Admin дополнительно меняет роли; нельзя лишить систему последнего администратора.
Изменение видео/доступа — только владельцем. Лайки, комментарии, подписки и жалобы — после входа с проверкой соответствующих объектных прав.
Владелец выдаёт доступ по точному нормализованному email уже зарегистрированного
пользователя; video_grants хранит user_id, а не email или публичную ссылку.
Неизвестный email отклоняется без создания приглашения. Выдача и отзыв доступны
только владельцу; повторная выдача не создаёт дубль. Поиск пользователей по части email не нужен.

## Сессии, API и UI

- Пароли Argon2id; ограничить конкурентность хеширования и частоту входа/регистрации.
- Случайные 256-битные непрозрачные сессии; в БД хеш токена, срок и отзыв. При входе ротация, при выходе отзыв.
- Cookie HttpOnly, SameSite=Lax, Secure при HTTPS. Роль проверяется по БД, не доверяется клиенту.
- CSRF-токен и Origin для изменяющих запросов, включая вход и загрузку. Swagger использует тот же механизм через interceptor, а не отдельный JWT.
- Один origin; открытый CORS не включать. Доверять forwarded-заголовкам только от собственного Nginx.
- Роль, владельца, ключи файлов и состояния обработки нельзя массово назначить через входную схему.
- Jinja2 autoescape, JavaScript textContent, ограничения длины, параметризованный SQL, CSP и nosniff.
- Локальные субтитры: `.vtt` до 1 МиБ проверяется до чтения, затем заголовок
  WEBVTT и штатный парсер браузера. CSP `media-src 'self' blob:` разрешает
  локальный TextTrack; script-src/connect-src/object-src не расширяются.
  Файл не отправляется в API, Blob освобождается при замене/ошибке/уходе.
  Настройки плеера не содержат ID видео, URL, имён файлов или содержимого cues.
- Имена, метаданные, поиск, комментарии и причины решений отклоняют NUL и
  некорректные Unicode-суррогаты до записи/сравнения в PostgreSQL. Пароль не
  обрезается и не нормализуется; некорректный UTF-8-суррогат отклоняется до Argon2.
  API возвращает 422 без исходного пароля; некорректный URL-path может раньше
  получить 400 от Nginx.
- Закрытые объекты снаружи не раскрывать через разные ошибки существования. Для недоступного видео/медиа — 404; для неавторизованной мутации — 401, отсутствующей роли — 403.

### Реализованные ограничения учётных записей

- Argon2id: 19 МиБ, две итерации, один поток; не более двух хеширований на
  процесс API, при занятости — 503/Retry-After. Неизвестный email проверяется
  через фиктивный хеш; текст ответа одинаков с неверным паролем. Параметры
  соответствуют [минимуму OWASP](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html).
- Срок анонимной сессии — 30 минут, авторизованной — 7 суток, без продления
  при чтении. Вход/регистрация отзывают старую cookie; выход отзывает её и
  выдаёт анонимную. Повторный анонимный выход не создаёт строк. Выход остаётся
  доступным после исчерпания общего лимита IP.
- Все auth POST требуют существующую сессию, точный Origin и 64-символьный
  ASCII CSRF-токен; некорректное значение даёт 403. CSRF связан с текущим
  непрозрачным токеном сессии. Ответы сессий и страниц — no-store.
- Формы входа/регистрации обновляют CSRF через same-origin GET session перед
  отправкой; автоматического повторения POST после 403 нет. HTML GET/HEAD с
  loopback-псевдонима переводится на фиксированный PUBLIC_ORIGIN после
  TrustedHost и до сессии. Адрес назначения не берётся из входного Host или
  query. API/медиа/статика и мутации не перенаправляются; точный Origin и
  CSRF продолжают проверяться. Открытый CORS и дополнительные origin не добавлены.
- Окно частоты — 15 минут: вход/регистрация вместе до 100 попыток с IP,
  вход до 10 на email, регистрация до 5 на email; создание анонимных сессий
  до 120 с IP. Ключи — SHA-256, счётчики общие в PostgreSQL. Неудачная
  аутентификация не откатывает счётчик. Это ограничение подбора, а не
  заявленная защита от распределённой атаки.
- Адрес клиента передаёт собственный Nginx в X-FoxTube-Client-IP, перезаписывая
  значение клиента. API не публикуется на хост; X-Forwarded-* не доверяются.
  Публичный HTTPS origin включает Secure для cookie.
- Все изменяющие `/api/v1/` запросы ограничены 16 КиБ в ASGI, включая
  chunked-запрос без Content-Length. Единственное исключение — точный
  PUT `/api/v1/videos/{UUID}/source`, ограниченный 500 МиБ; похожий путь
  не отключает JSON-лимит. Nginx дополнительно ограничивает auth POST.
  Ограничения email/имени/пароля действуют на сервере;
  лишние role/user_id отклоняются. Ошибки валидации не возвращают исходный
  ввод, ошибки БД — строку подключения или запрос.
- API не может напрямую назначать/менять role: INSERT users разрешён только на
  id/email/password_hash/display_name, UPDATE — только password_hash.
  Worker не читает users и хеши паролей; для очистки имеет лишь необходимые
  столбцы sessions/auth_rate_limits и DELETE. Миграции выполняются отдельной ролью.
- Очистка раз в минуту удаляет до 500 сессий, истёкших или отозванных более
  суток назад, и до 500 истёкших ограничителей. Сессия перестаёт давать
  доступ сразу после отзыва/истечения, независимо от физического удаления.

## Социальные действия, модерация и роли

- Лайки, комментарии, их удаление и сохранение в плейлист проверяют readable.
  Сначала блокируется строка видео, затем ACL повторно читается отдельным
  statement после ожидания блокировки. Отозванный за это время grant не
  остаётся действительным из старого снимка READ COMMITTED.
- Комментарий удаляет автор или владелец видео с сохранённым правом просмотра;
  для недоступного/чужого/несуществующего объекта используется одинаковый 404.
  NUL и некорректные Unicode-суррогаты в текстовых полях отклоняются до БД.
- Публичность плейлиста не открывает его приватные ролики. Записи и счётчики
  фильтруются до пагинации; приватный плейлист доступен только владельцу.
  Подписка на свой канал запрещена. Лимиты: 100 плейлистов и 1000 подписок
  на пользователя, 500 элементов в плейлисте, 10000 комментариев к видео;
  изменяющие API имеют общий в PostgreSQL контроль частоты.
- Жалобы доступны только зарегистрированным зрителям с правом просмотра;
  одна открытая жалоба на пару пользователь/видео, до 20 попыток за 15 минут.
  Moderator/admin видят служебную карточку без приватного названия и ссылки
  просмотра, если readable запрещает доступ.
- Изменение роли, скрытие/восстановление и закрытие жалобы выполняются через
  SECURITY DEFINER-функции с фиксированным search_path, параметризованными
  значениями и отозванным PUBLIC EXECUTE. Runtime API имеет только EXECUTE;
  прямые изменения `users.role`, `moderation_status` и истории запрещены.
- Общая транзакционная advisory-блокировка сериализует изменения ролей и
  модерации. Роль повторно проверяется после её получения. Два конкурирующих
  понижения не удаляют последнего admin. Действие и событие аудита атомарны;
  ошибка записи аудита откатывает само действие.
- Первого admin назначает CLI под ролью миграций существующему аккаунту,
  только если администраторов ещё нет. Публичного HTTP bootstrap и
  стандартных привилегированных паролей нет. Демо создаёт только обычные роли.

Демо хранит случайные пароли в `secrets/demo/manifest.json` с правами 0600,
атомарной записью и отдельной блокировкой. Manifest/lock должны быть обычными
файлами; symlink и FIFO отклоняются. Внутренний HTTP-клиент использует только
`http://nginx:8080` и не следует redirects. Исключение Secure-cookie ограничено
этим адресом внутри Compose; публичные сессионные cookies сохраняют Secure
при HTTPS. Manifest, `.env` и реальные медиа исключены из Git/образа/архива.

## Все пути к медиа

- Одна политика для страниц, API, списков, поиска, плейлистов, комментариев, счётчиков, превью и MP4.
- Для медиа проверять GET, HEAD и Range до выдачи/обработки условного запроса.
- Nginx internal location + X-Accel-Redirect; прямой URL к тому и исходникам отсутствует.
- Пути строятся из серверных UUID/ключей; имя загрузки не становится путём. Проверять границы каталога и не следовать пользовательским ссылкам.
- Cache-Control: private, no-store; ответ из кеша не обходит ACL после смены приватности.
- Отзыв/скрытие/удаление запрещает следующие запросы. Открытая передача может завершиться; скачанные байты не отзываются.

## Недоверенное видео и ресурсы

- Доступ и резервирование до тела; реальные байты, время, размеры, потоки и продолжительность проверяются сервером. MIME и расширение недостаточны.
- При ffprobe/FFmpeg ограничивать разрешённые контейнеры, протоколы и декодеры. Только локальные входы, никакой загрузки URL/плейлистов из сети.
- subprocess без shell и интерактивного stdin; минимальное окружение без секретов; ограниченный stderr/stdout, тайм-ауты и корректное завершение дерева процессов.
- Непривилегированный worker, read-only rootfs где возможно, только необходимые тома, внутренние сети и роль БД с минимальными правами. ffprobe изолирован так же, как FFmpeg.
- Жёсткие лимиты контейнера дополняют настройки потоков FFmpeg. Резервы/квоты общие в PostgreSQL, не локальные счётчики процесса API.
- Потеря аренды запрещает публикацию результата. Сбой обработки не меняет private/hidden/deleted.

## Эксплуатация и ревью

Реализованные границы видео: JSON ограничен 16 КиБ, исходник — 500 МиБ
как в Nginx, так и по реальным байтам в API. До чтения тела проверяются
сессия/CSRF/владелец и общий PostgreSQL-резерв. Черновик — один на пользователя
с резервом на пять минут; начатая передача — до 30 минут, активная аренда
120 секунд. Частота создания — 10 на пользователя и 20 с IP за 15 минут.
Глобальные лимиты и квоты сериализуются короткой advisory-транзакцией.

FFmpeg/ffprobe получают только серверный локальный путь, whitelist контейнеров,
кодеков и протокола file, минимальное окружение, ограниченные вывод/время/
потоки. Результат проверяется повторно; жёсткий предел MP4 не превращается
в успешный усечённый ролик. Файлы каждой попытки публикуются атомарно;
токен/аренда проверяются перед READY. Очистка ограничена пачками, продолжает
обход старых каталогов между проходами и сохраняет квоту при ошибке удаления.

API может обновлять только пользовательские поля и поля загрузки видео.
Worker — только технические поля обработки/учёта; ему не выданы UPDATE
visibility/moderation_status и доступ к паролям. Runtime не имеет DDL.

Секреты создаются установщиком, конфигурация с ними доступна только владельцу.
Наружу выходит Nginx; БД и API не публикуются. Ubuntu bootstrap выбирает один
назначенный RFC1918 IPv4 и подключённую подсеть, согласует bind/public origin
и проверяет итоговый Compose. По умолчанию до Docker DNAT отдельная таблица
nftables отбрасывает обращения к IP/порту приложения извне этой подсети.
`--listen-all` явно выбирает bind `0.0.0.0`, сохраняя фильтрацию источников
для всех локальных назначений веб-порта. Отдельный `--allow-any-source`
снимает ограничение источников IPv4 только в собственной таблице;
он заменяет прежний DROP атомарно. `--allow-subnet` добавляет только явно
указанные RFC1918 CIDR и несовместим с any-source. Политика сохраняется в `.env`;
обычный повтор не возвращает прежнее ограничение. Ни один из режимов не
публикует API/БД или IPv6 и не расширяет допустимые Host/Origin/CORS.
Авторизация, CSRF, ACL медиа и лимиты продолжают действовать. Правила
восстанавливает oneshot systemd до запуска Docker; повтор обновляет только
собственную таблицу атомарно. SSH, UFW и чужие таблицы не изменяются.
Опциональный `--tcp-mss` после диагностики PMTU только уменьшает объявленный
MSS входящих IPv4 SYN локального веб-порта; он не расширяет доступ и не меняет
маршруты, ICMP или SSH. Настройка по умолчанию выключена.
Файлы systemd/rules с чужим содержимым или небезопасными правами не перезаписываются.
Автоматизация требует локальный Docker socket; конфликт порта и смена работающего
LAN endpoint вызывают отказ до замены фильтра. Это не защищает от администратора,
выполнившего глобальный flush, и не покрывает нестандартный Docker direct routing.
Подробности — [эксплуатация](development.md#локальная-сеть-и-firewall).
HTTPS обязателен для публичного размещения.
Роль миграций отделяется от runtime; права worker ограничены обработкой видео/заданий.
Не логировать пароли, cookies, CSRF и приватные файлы. Аудит хранит жалобы,
решения, изменения ролей и модерации без секретов. Изменения владельцем
privacy/grants пока не аудируются. Архив не включает .env, реальные загрузки и резервные копии.

Ревью выдаёт подтверждённые дефекты с условием воспроизведения и последствиями;
гипотезы отделяются от фактов. Проверки проводятся только на локальной/выделенной
тестовой среде. Отсутствие найденных дефектов не означает доказанную безопасность.

## Миниплеер и внутренняя навигация

Постоянный плеер не даёт дополнительных прав. Перед вставкой каждой полученной
страницы проверяются origin, итоговый URL после redirect, список допустимых
HTML-маршрутов, версия shell и UUID зрителя. Скрипты из полученного содержимого
не исполняются; модули подключены один раз и имеют lifecycle с отменой запросов.
CSRF берётся из новой страницы; busy/dirty формы оставляют обычную навигацию.

Доступ к текущему ролику повторно проверяется через API при переходе, возвращении
фокуса/видимости и каждые 30 секунд видимого миниплеера. Проверяется и UUID сессии.
Успешный вход/выход передаёт другим вкладкам сигнал через BroadcastChannel;
он не содержит данных аккаунта и только запускает такую же серверную проверку.
Если канал недоступен, остаются проверки при фокусе, навигации и по таймеру.
Недостаточно одного 200: требуются тот же id и защищённый playback URL; скрытое
видео владельца с `playback_url:null` закрывается. Устаревший ответ не должен
изменять новый плеер или отменённый переход. При отказе доступа/смене аккаунта
очищаются src, poster, tracks, Blob URL, название и обработчики; при сетевом сбое
просмотр приостанавливается с сообщением. Закрытие освобождает медиа, не меняет БД.

Новый GET/HEAD/Range по-прежнему проверяется сервером. Фокус и опрос не означают
мгновенный отзыв уже полученных байтов или начатой передачи. Предпросмотр всегда
начинается без звука; звук включается пользователем. При блокировке play браузером
обрабатывается отказ, доступна явная кнопка воспроизведения/включения звука.

## Рекомендации и автопереход

GET `/api/v1/videos/{id}/recommendations` сначала проверяет доступ к исходному
ролику. Недоступный источник даёт 404; собственный hidden/non-READY без playback
даёт пустой список. Предикат `readable` применяется к кандидатам до сортировки
и LIMIT, независимо от роли зрителя. Сервис общий с HTML; пользовательские
названия экранируются Jinja2, в отсчёте устанавливаются через textContent.

После отсчёта повторно проверяются сессия, текущий и следующий ролики, включая
точный защищённый playback URL. Перед вставкой следующего HTML проверяется
личность зрителя и наличие ожидаемого плеера. После каждого ожидания действует
проверка актуальности попытки: отмена, выключение, закрытие, смена ролика/сессии,
переход, скрытие вкладки или незавершённая форма запрещают поздний переход.
При сетевом сбое автоматического обычного redirect нет. Скрытие вкладки отменяет
текущий отсчёт; возврат сам по себе его не возобновляет. В localStorage сохраняются
только булевы настройки меню и autoplay, без очереди, URL или истории просмотров.
Новые медиа-запросы по-прежнему проходят серверный ACL.
