# Проверка инфраструктуры FoxTube — 2026-11-11

## Результат и границы

**PASSED:** установка одной командой на чистой Ubuntu 22.04.5, создание демо,
повторный bootstrap без изменения данных и секретов, загрузка после reboot,
LAN firewall и явный режим `--listen-all --allow-any-source`.

Найден и исправлен дефект P2 проверки владения nftables: наличие маркированных
правил раньше разрешало `flush table` даже при добавленной администратором
пустой цепочке, set, map, counter или quota. Теперь установщик проверяет все
объекты таблицы, имена и параметры собственных базовых цепочек и отказывается
от изменения чужой конфигурации. Совместимость с прежним немаркированным
правилом `ct direction reply return` сохранена.

Ubuntu 24.04 **не проверена** в этом прогоне. На гипервизоре доступен ISO
24.04.1 Server, но отдельную установку не запускали. Браузерная приёмка и
нагрузка выполняются главным агентом отдельно, после передачи этой ВМ;
инфраструктурные HTTP-проверки их не заменяют.

### Firewall и проверка владения

- Реальные nftables Ubuntu 22.04: в отдельном namespace `nft --check`, применение,
  повторное применение и распознавание собственного JSON прошли для LAN,
  wildcard/any-source и опционального MSS 1200. В последнем случае три правила,
  в остальных два. Сохранённый реальный Jammy JSON предыдущей версии принят.
- Неподключённые сторонние chain, set и counter в namespace вызвали отказ
  валидатора; JSON таблицы после отказа совпал с исходным.
- В настоящую таблицу временной VM 951 поочерёдно добавлены пустая чужая chain
  и set. Вызов финального `configure_lan.py .env` завершился отказом; чужой
  объект, `.env`, три system-файла, контейнеры и их время запуска сохранились.
  После проверки удалены только два созданных проверкой объекта.
- В LAN-режиме HTTP от отдельного namespace с источником `10.77.51.2`
  запрещён; увеличился счётчик DROP собственного правила.

Для следующей браузерной приёмки временная ВМ переведена в уже авторизованный
пользователем режим любых IPv4-источников. При изменении bind остановлен только
Nginx; API, worker и PostgreSQL не пересоздавались:

```sh
docker compose stop nginx
python3 scripts/configure_lan.py .env --listen-all --allow-any-source
docker compose up -d --no-build --wait --wait-timeout 120 nginx
python3 scripts/configure_lan.py .env
bash scripts/bootstrap.sh --demo
systemctl reboot
```

Обычный повтор без сетевых флагов сохранил `0.0.0.0:8080` и any-source.
После reboot изменились boot ID и время запуска процессов; контейнеры,
образы, `.env`, данные и медиахэши сохранились, все четыре контейнера healthy.
`foxtube-lan-firewall.service` enabled/active; завершение его ExecStart
4 952 768 мкс после начала boot предшествовало старту Docker 5 001 828 мкс.
В таблице нет старого DROP. Источник `10.77.51.2` получил readiness HTTP 200;
запрос из локального Docker bridge также вернул HTTP 200.

После reboot опубликован **только Nginx, `0.0.0.0:8080/tcp`**. У API,
PostgreSQL и worker нет Host PortBindings, IPv6-публикации нет. Canonical origin
остаётся `http://192.168.1.129:8080`. Это тестовая HTTP-установка; публичное
размещение требует HTTPS. ВМ сохранена для дальнейших QA и capacity-проверок.
