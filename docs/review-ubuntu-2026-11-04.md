# Проверка развёртывания на чистой Ubuntu — 2026-11-04

Требование: установка из распакованного архива одной командой и полный
пользовательский сценарий. По указанию пользователя проверяется Ubuntu 22.04
на предоставленной ВМ. Неудачные попытки возвращаются к исходному снимку;
повтор поверх частично установленного Docker чистой проверкой не считается.

## Окружение и откат

Ubuntu 22.04.5 LTS, amd64, ядро 5.15.0-202-generic; 4 vCPU, 8196 МиБ RAM,
диск 100 ГБ, перед началом около 84 ГБ свободно. SSH `root@192.168.1.16`.
Proxmox `192.168.1.4`, ВМ **501 FoxTube**; соответствие подтверждено MAC.
Единственный записываемый диск — scsi0, qcow2. Остальные ВМ не изменялись.

Перед загрузкой проекта ВМ выключена и создан снимок
`foxtube-clean-20261104` всех её записываемых дисков. В исходном состоянии
нет Docker, его apt-источника/ключа, контейнерных данных и `/opt/foxtube`.
Сохранён контрольный список 610 пакетов и SHA-256 ключевых настроек ОС,
сети и публичного SSH host key; секретные ключи не читались.

Восстановление выполняется **снаружи гостевой ОС**, через Proxmox:
остановить 501 → rollback снимка → запустить → дождаться SSH → сверить
пакеты/настройки и отсутствие Docker, проекта и контрольного файла.
Восстановление сначала проверено отдельным контрольным файлом: passed.
Это восстановление диска ВМ, а не `apt purge` или удаление Compose-томов.

## Найденное и исправленное

| Проблема | Воспроизведение | Исправление |
|---|---|---|
| Установщик отклонял Ubuntu 22.04 до установки Docker | Первый запуск `bash scripts/bootstrap.sh --demo`: exit 1, сообщение о поддержке только 24.04 | Поддержаны точные пары 22.04/jammy и 24.04/noble; apt suite выбирается по ОС |
| Обрыв загрузки ключа мог оставить непустой повреждённый `docker.asc`; повтор пропускал загрузку | Изолированный curl записывает часть файла и возвращает ошибку; регрессия проверяет отсутствие конечного файла и успешный повтор | Ключ и sources сначала записываются во временные файлы, публикуются целиком; временные файлы удаляются при ошибке. Чужие отличающиеся файлы/симлинки сохраняются с явным отказом |

Установка через официальный apt-репозиторий соответствует
[Docker Ubuntu documentation](https://docs.docker.com/engine/install/ubuntu/),
где перечислены Jammy 22.04 и Noble 24.04. Это не доказательство отдельного
реального прогона на Ubuntu 24.04.

Сам bootstrap сохраняет данные и не откатывает изменения ОС при ошибке.
Для этих испытаний автоматический возврат обеспечивает внешний контроллер
снимка. Его исправленная обработка отказа не зависит от успешной записи
отчёта/выгрузки доказательств: три локальных проверки ошибок записи и экспорта
подтвердили один вызов восстановления в каждом случае. Полная потеря
контроллера/SIGKILL требует внешнего восстановления сохранённого снимка.

Вся успешная попытка с дополнительной сборкой Chrome заняла 317,03 с.
Повтор установщика и перезагрузка внутри неё намеренно проверяли существующие
данные. Каждая новая попытка после отказа начиналась с восстановленной чистой ОС.
Права moderator/admin и Swagger upload повторно на этой ВМ не проверялись;
они проверены предыдущим изолированным комплексным прогоном.

Приложение оставлено в `/opt/foxtube`, четыре постоянных сервиса healthy.
На хосте опубликован только `127.0.0.1:8080`; PostgreSQL/API не опубликованы.
Доступ с компьютера пользователя через SSH-туннель (локальный 8080 должен быть свободен):

```bash
ssh -N -L 8080:127.0.0.1:8080 root@192.168.1.16
```

Затем открыть [FoxTube](http://localhost:8080) или [Swagger](http://localhost:8080/docs).
Демо-пароли доступны только на сервере в `/opt/foxtube/secrets/demo/manifest.json`;
в отчёт и архив они не включены. Четыре QA-аккаунта имеют случайные пароли,
оставшиеся только в памяти завершённого теста; для ручного входа используйте
новую регистрацию или демо-аккаунт.

## Границы

Полный прогон на Ubuntu 24.04, публичный HTTPS, другие браузеры/физический
телефон и нагрузка на 4 CPU/8 ГБ в эту проверку не входят. После перезагрузки
проверены записи активных сессий в БД; сохранённая браузерная cookie повторно
не использовалась. Перемотка задаётся через currentTime с проверкой дальнейшего
воспроизведения; ползунок мышью/касанием отдельно не проверен.
Предыдущие интеграционные, аварийные и локальные нагрузочные результаты
сохранены в [комплексном отчёте](review-comprehensive-2026-11-04.md).
