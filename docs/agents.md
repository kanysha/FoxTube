# Агенты, навыки и инструменты

## Как устроено

AGENTS.md автоматически задаёт общие инструкции. Подробности читаются по задаче,
а docs/status.md хранит краткую передачу контекста между сессиями.
Навык описывает повторяемый процесс; агент выполняет отдельное поручение с собственным контекстом.

| Агент | Когда нужен | Область изменений | Результат |
|---|---|---|---|
| foxtube_fullstack | Законченная функция API/экрана/БД | Назначенные модули, web, миграции | Реализация и проверенные сценарии |
| foxtube_video | Загрузка, очередь, обработка, Range | Назначенные media/video/deploy-файлы | Рабочий конвейер и проверки сбоев |
| foxtube_security | Изменены права, сессии, медиа или внешняя поверхность | Без редактирования | Подтверждённые риски и способы исправления |
| foxtube_qa | Законченная вертикаль или приёмка | Назначенные тесты/fixtures/отчёты | Passed/failed/blocked и воспроизводимые дефекты |

Профили: .codex/agents/*.toml. Модель, права, провайдер и MCP наследуются.
Режим без редактирования для security — инструкция поведения, не техническая изоляция.
Конфигурация ограничивает параллелизм тремя дочерними агентами; основной агент интегрирует результат.
Политики разрешений проекта не ослабляются и глобальные настройки не меняются.

Перед делегированием основной агент даёт: цель; входные файлы/контракт;
разрешённые области записи; ограничения; ожидаемую проверку.
Общие модели/миграции/контракты сначала согласуются, затем редактируются одним владельцем.
Ревью и приёмка идут после стабилизации соответствующего изменения. Для маленькой правки достаточно основного агента.
Если специализированный spawn недоступен, основной агент читает профиль и выполняет эту роль сам;
при доступном обычном subagent можно передать ему профиль явно. Нельзя выдавать такой запуск за автоматическое обнаружение профиля.

## Навыки проекта

| Навык | Назначение |
|---|---|
| $foxtube-feature | Вертикальная разработка: модель → API → экран → проверка |
| $foxtube-video | Контракт передачи/обработки/выдачи и аварийные состояния |
| $foxtube-security | Проверка реального пути доступа и подтверждение дефектов |
| $foxtube-acceptance | Проверки по требованиям и доказательная приёмка |

Навыки находятся в .agents/skills и доступны по смыслу задачи или явному $имени.
Новые навыки не требуют внешних аккаунтов/MCP; никаких скрытых сетевых зависимостей.

Примеры поручений:

- «Используй foxtube_fullstack: реализуй регистрацию и вход по $foxtube-feature».
- «Используй foxtube_video: реализуй lease и восстановление задания по $foxtube-video».
- «Пусть foxtube_security проверит приватность MP4, HEAD и Range; файлы не менять».
- «Пусть foxtube_qa проверит A4/A6 и приложит команды и воспроизведения ошибок».

## Инструменты

| Инструмент | Применение | Где нужен |
|---|---|---|
| Codex, rg, Git | Работа с кодом, поиск, история и diff | Хост; Git инициализирован 2026-11-04 |
| Python 3.11+ | Проверка агентной обвязки без зависимостей | Хост |
| Docker Engine + Compose | PostgreSQL, API, worker, Nginx, изолированные проверки | Хост/Ubuntu |
| Python 3.12 + uv | Окружение приложения и lock-файл | Образ приложения; локально при необходимости |
| FFmpeg + ffprobe | Настоящая обработка и валидация | Образ worker/тестов; установка на хост не обязательна |
| Ruff + mypy | Линтинг/формат и типы прикладного кода | Development-образ |
| pytest + HTTPX | Unit и интеграционные проверки | Dev/test-окружение |
| Playwright Python + Google Chrome | E2E, H.264 и визуальная проверка | Отдельное тестовое окружение |
| ShellCheck, pip-audit | Shell-скрипты и зависимости перед поставкой | Dev/test-окружение |

Node/npm не требуются простому фронту. GitHub-коннектор пригодится после появления
репозитория и PR, но для локальной разработки не обязателен. Дополнительные MCP-серверы
не устанавливаются, пока конкретная задача не требует их возможностей.

## Действующие команды

Из корня проекта:

```bash
make agents-check
make doctor
make up
make check
make test
make test-browser
make test-resilience
make test-capacity
```

Первая команда проверяет локальные TOML, ссылки и метаданные навыков, без сети и установки.
Вторая дополнительно показывает инструменты и доступность Docker Engine. Отсутствующий
инструмент даёт предупреждение; ошибка обвязки — ненулевой код выхода.
Режим для CI/автоматизации с обязательными хостовыми инструментами:

```bash
python3 scripts/check_agent_setup.py --tools --strict-tools
```

make up собирает и запускает каркас с миграциями. make check запускает проверки
кода в development-образе, make test — отдельное интеграционное окружение,
make test-browser — загрузку и воспроизведение H.264 в изолированном Chrome.
Для этих проверок приложения Python, uv и FFmpeg на хосте не нужны;
достаточно Docker/Compose и bash. Для `make test-resilience` и `make test-capacity`
дополнительно нужен Python 3 на хосте; сценарии и границы описаны в [testing.md](testing.md).
Установка на Ubuntu и настройки — в [development.md](development.md).

## Обнаружение и совместимость

Формат сверяется с Codex CLI 0.166.0-alpha.5.1 и официальной документацией.
Локальная проверка debug prompt-input подтвердила обнаружение четырёх профилей
в описании доступных ролей spawn и четырёх проектных навыков в контексте.
Проект должен быть открыт в корне FoxTube; project config загружается для доверенного
проекта. Глобальные trust/permissions автоматически не меняются. После изменения
AGENTS.md/config начать новую сессию; если навыки не появились — перезапустить Codex.
Для предсказуемого обнаружения проектной конфигурации открывайте корень репозитория.
