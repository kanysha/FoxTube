## Исправления

Ошибка входа/регистрации по `http://127.0.0.1:8080` воспроизведена:
при настроенном origin `http://localhost:8080` POST с корректной cookie и CSRF
возвращал 403 до проверки пароля. На localhost тот же сценарий доходил до
проверки учётных данных. Это несовпадение origin, а не отказ PostgreSQL.

HTML GET/HEAD с loopback-псевдонима теперь переводит браузер на фиксированный
PUBLIC_ORIGIN до создания сессии. TrustedHost выполняется раньше; API, статика,
медиа и мутации не перенаправляются. Формы входа/регистрации перед единственным
POST получают текущую сессию без кеша, поэтому устаревший токен после ротации
cookie в другой вкладке не мешает отправке. Автоматического повтора POST нет.
Произвольное несовпадение схемы/порта при одинаковом имени не исправляется.

Расширенный плеер сохраняет нативный HTML5 video и один защищённый MP4.
Доступны скорость, повтор, широкий режим, PiP при поддержке браузером,
локальные WebVTT и сохранение настроек. Устранён P2 медленного двойного клика:
второй mousedown отменяет одиночный click; интервал ожидания увеличен до 500 мс.
Проверяются настоящие single clicks и double clicks с интервалом 0/350 мс,
на паузе и при воспроизведении.

Тест смены источников сохраняет настоящий HTTP document от Nginx. Второй
source добавляется во время разбора DOM до запуска deferred player.js,
вместо подмены всего HTTP-ответа. Проверки готовности и воспроизведения
сохранены; CSP и браузерные ограничения не отключаются. Диагностика не пишет
HTML, URL медиа, cookies, токены, пароли или текст исключений.

Причина прежнего `readyState=0/networkState=3/enhanced=false` подтверждена
сравнением в отдельном Compose на `http://nginx:8080`: настоящий document
прошёл; прежний fulfilled document дал `InsecureLocalNetwork` в Chrome CDP
и ERR_FAILED всех ресурсов; новый observer fixture прошёл весь helper с
сохранением позиции/скорости/громкости и продолжением реального воспроизведения.
Изменение Content-Length отдельно не устраняло этот отказ. Артефакт:
`.artifacts/review-2026-11-08/source-fixture-lna.json`. Браузерные security flags
не применялись, временные контейнеры и только их тома удалены.

После прохождения расширенного плеера выявлен конфликт прежнего privacy helper:
клик по video ставил отложенный toggle, а следующий программный play запускал
видео раньше таймера, после чего toggle ставил его на паузу. Начало проверки
заменено настоящим нажатием центральной кнопки Play; требования `currentTime>1`,
seek к 7 с и продолжение до `>8` сохранены. Причина и правка отдельно просмотрены QA.

## Применение и проверка работающих экземпляров

Оба экземпляра используют `foxtube-app:player-20261108`. Обновлены только
API/worker, Nginx получил проверку конфигурации и reload. ID, образ, время
старта, health и тома PostgreSQL/Nginx не изменились; миграционные Python-файлы
совпали с прежними. Все четыре сервиса healthy, файловые тома сохранены.

| Экземпляр | Адрес | Пользователи/видео до и после |
|---|---|---|
| Локальный Docker | `http://localhost:8080` | 8 / 15 |
| Ubuntu `192.168.1.16` | `http://192.168.1.16:8080` | 26 / 22 |

`http://127.0.0.1:8080/login` переводит на localhost до создания cookie.
Это проверено через настоящий опубликованный endpoint с хоста. HTTP-проверка
с корректной сессией теперь достигает проверки учётных данных (401 для
несуществующей учётной записи), вместо прежнего 403 Origin.

Chrome дополнительно проверил оба работающих экземпляра: формы достигают
проверки пароля/валидации регистрации, SHA256 плеера/CSS/auth совпадают с
проверенным исходным кодом, существующее публичное видео воспроизводится,
перематывается и продолжает играть; двойной клик 350 мс открывает fullscreen
без снятия паузы. Ошибок JavaScript нет. Для локального Chrome в контейнере
использован HTTP-прокси к Nginx с сохранением Host/Origin; отдельно проверен
настоящий host endpoint. Сервер проверен напрямую. Успешные создание аккаунта
и вход проверены в изолированном E2E; на рабочих данных новые аккаунты/видео
не создавались, выполнялись только заведомо неуспешные auth-проверки и чтение.

Финальный read-only network probe с клиентского компьютера: `/health/ready`,
полная главная, `/docs`, локальные Swagger assets и OpenAPI прошли; 8080/22
доступны, 5432/6379/8000 отвергают соединение. Сервер сохраняет веб-bind
`0.0.0.0:8080` и any-source IPv4; наружу публикуется только Nginx.
Политика MSS=1200 из предыдущего этапа не изменялась.

До применения сохранены приватные копии конфигурации и прежний образ
`foxtube-app:rollback-player-20261108`; для серверного Docker containerd
совпадение образа отката проверено по platform manifest (config digest старого
контейнера отличается от OCI index/tag identity). Подготовленный серверный
образ проверен по SHA256 всех файлов app, pyproject.toml и uv.lock до замены.
Копии: локально `/tmp/foxtube-player-backup-20261108`, на сервере
`/root/foxtube-player-backup-20261108-runtime`. Секреты в артефакты не включены.
Проблемы SSH и проверки идентификатора образа перед применением не меняли
конфигурацию или рабочие сервисы; финальный запуск завершён успешно.
