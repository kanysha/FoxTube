## Критичные ситуации

- Сохраняются проверки сессий, CSRF/Origin, IDOR, ограничений загрузки,
  настоящего FFmpeg, аренды заданий и защищённой раздачи медиа через Nginx.
- Каналы применяют общий ACL до счётчиков и пагинации; API профиля не раскрывает
  email автора. Grant и его отзыв меняют доступные видео следующего запроса.
- Лайки и подписки идемпотентны под гонкой. Недоступные видео и элементы
  публичных плейлистов не раскрываются через счётчики. Отзыв grant во время
  ожидания блокировки учитывается отдельной свежей проверкой READ COMMITTED.
- Удаление комментария к приватному ролику не раскрывает существование
  комментария различающимися ответами. Текст комментария отображается как текст.
- Смена роли и модерация заново проверяют текущую роль под общей короткой
  блокировкой. Конкурентные понижения не удаляют последнего admin.
  Ошибка записи аудита откатывает защищённое действие целиком.
- Роль moderator/admin не открывает приватный MP4 или превью, включая HEAD/Range.
  Служебная карточка недоступного видео не показывает его название и ссылку.
  Worker после скрытия сохраняет hidden/private при завершении обработки.
- API не имеет прямой записи `users.role`, `videos.moderation_status` или журнала;
  SECURITY DEFINER-функции с фиксированным search_path недоступны PUBLIC/worker.
- Демо создаёт 6 аккаунтов, 12 настоящих READY с MP4/JPEG, комментарии и
  плейлисты через HTTP. Два запуска не дублируют записи; третий не возвращает
  удалённый вручную комментарий. Посторонние аккаунты сохраняются;
  после наполнения активные сессии этих демоаккаунтов отозваны.
- Manifest демо с паролями имеет 0600, отдельный flock, атомарную запись и
  запрет symlink/FIFO. Secure cookie разрешена по внутреннему HTTP только
  для точного `nginx:8080`; перенаправления с Host/Origin/телом запрещены.

## Что исправлено при ревью

Подтверждены и закрыты гонки ACL после ожидания, различающиеся ответы удаления
комментариев, некорректный подсчёт плейлистов и невозможные для PostgreSQL строки.
Из-за NUL в имени/метаданных или Unicode-суррогата в пароле запрос мог закончиться
ошибкой сервера. Валидация теперь отклоняет их до записи/хеширования без отражения
пароля в ответе. Причины модерации проверяются так же.

Дефект поиска воспроизведён реальным HTTP: `/search?q=bad%00text` и
`/api/v1/videos?q=bad%00text` возвращали 503. Общий `DatabaseText` теперь
проверяет query до ILIKE, ожидаемый ответ — 422. Непригодный текст и длина
короткого адреса канала также проверяются до БД.

Подготовка браузерного сценария выявила выход без обязательного JSON `{}` в
демо-клиенте: сервер возвращал 422, активные демосессии оставались до истечения.
Запрос исправлен; повторный интеграционный тест проверяет ноль активных
пользовательских сессий после каждого из первых двух наполнений. Скрипт Chrome
теперь сбрасывает старый успешный report.json до подготовки окружения, чтобы
ошибка запуска не выглядела успешным результатом предыдущего прогона.

Локальный запуск выявил несовместимое с macOS `chmod 700 --`: аргумент `--`
убран для уже абсолютного пути каталога демо. Повтор bootstrap прошёл.
На снимках QA обнаружены неподдерживаемые шрифтом значки лайка/плейлиста и
кнопка «Ещё комментарии», которую CSS показывал вопреки `hidden`.
Значки заменены SVG, скрытие закреплено отдельным правилом. Chrome-регрессия
ждёт загруженный комментарий и проверяет отсутствие лишней кнопки; полный
прогон и независимый просмотр новых снимков прошли.

Ревью не доказывает отсутствие всех уязвимостей. Аудит пока не фиксирует изменения
приватности/grant владельцем; фиксирует жалобы, решения, скрытие/восстановление,
роли и первое назначение admin. Уже переданные байты и начатый поток отозвать нельзя.
