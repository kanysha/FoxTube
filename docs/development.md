# Запуск и разработка

Реализованы учётные записи, видеоконвейер, каналы, лайки, комментарии, подписки,
плейлисты, жалобы и управление ролями. Все действия используют настоящие HTTP API
и PostgreSQL; worker обрабатывает видео и очищает старые сессии, резервы и файлы.

## Первый запуск

Из распакованного проекта на чистой **Ubuntu 22.04 или 24.04 LTS**:

```bash
sudo bash scripts/bootstrap.sh
```

Скрипт установит Docker Engine/Compose из официального apt-репозитория, если их
нет; создаст .env с отдельными случайными паролями БД; соберёт образ, запустит
PostgreSQL, выполнит миграции и дождётся готовности четырёх постоянных сервисов.
Одноразовый migrate не остаётся работать. Нужны доступ к интернету для установки,
репозитория образов и Python-зависимостей, 4 CPU/8 ГБ RAM и 40 ГБ свободного диска.
Образы и зависимости после сборки используются локально; Swagger не требует CDN.

Реальная установка на Ubuntu 22.04.5 без Docker, повторный запуск, Chrome и
перезапуск ВМ подтверждены [протоколом](review-ubuntu-2026-11-04.md).
Ubuntu 24.04 отдельно не проверялась.

На macOS/Linux с уже запущенными Docker Engine/Desktop и Compose:

```bash
bash scripts/bootstrap.sh
```

Команда работает и из другого каталога при указании пути к скрипту.
Открыть [FoxTube](http://localhost:8080), [Swagger](http://localhost:8080/docs),
[готовность](http://localhost:8080/health/ready). Фактический адрес выводится в конце запуска.
Требуется Docker Compose 2.20 или новее с поддержкой up --wait.

## Повторный запуск и данные

Если первый запуск выполнен через sudo, файл .env принадлежит root с правами 600.
В этом случае повторяйте запуск через `sudo bash scripts/bootstrap.sh` и используйте
sudo для команд Docker, пока права доступа не настроены отдельно.

Повторный bootstrap пересобирает приложение и применяет новые миграции;
существующий .env и данные в именованных томах сохраняются. После проверки
конфигурации скрипт перечитывает настройки Nginx, включая изменения его bind-файла.
Пароли не печатаются и хранятся в .env с правами 600. Файл не включается в образ/архив.
Не удаляйте .env, пока используете существующий том БД: заново созданные пароли
не изменят пароли ролей внутри PostgreSQL. Смена пароля — отдельная согласованная операция.

Из корня проекта:

```bash
docker compose ps
docker compose logs --tail 100 api worker nginx
docker compose down
bash scripts/bootstrap.sh
```

down останавливает и удаляет контейнеры/сеть, сохраняя pgdata и media.
Не добавляйте --volumes для рабочего окружения: это удалит данные.
При переносе проекта сохраняйте имя compose-проекта или подключайте существующие
тома явно; в штатном запуске используется имя foxtube.

## Испытания на чистой Ubuntu и откат

Сам установщик сохраняет существующие настройки и данные; ошибка останавливает
команду, но не отменяет уже выполненные изменения ОС и Docker. Для повторной
проверки именно на чистой ОС используйте внешний снимок всей тестовой ВМ.
До загрузки архива выключите выделенную ВМ, создайте снимок всех записываемых
дисков и проверьте восстановление. Управление гипервизором должно оставаться
доступным при отказе гостевой ОС. При неудаче сохраните обезличенные логи вне ВМ,
восстановите исходный снимок, загрузите Ubuntu и сверяйте пакеты/настройки,
отсутствие Docker, проекта и тестовых файлов. Только затем начинайте новую попытку.
Удаление контейнеров/томов и пакетов Docker не заменяет восстановление ОС.

## Настройки и доступ

[.env.example](../.env.example) описывает доступные параметры. Не копируйте пустые
пароли из примера; используйте bootstrap/configure. Чтобы изменить порт, задайте
FOXTUBE_PORT и согласованный FOXTUBE_PUBLIC_ORIGIN в .env. После изменения перезапустите bootstrap.
PUBLIC_ORIGIN содержит только схему, хост и необязательный порт, без пути,
параметров или учётных данных. Открывайте сайт именно по этому адресу:
localhost и 127.0.0.1 — разные origin. Изменяющий запрос с другого адреса вернёт 403.
По умолчанию порт привязан к 127.0.0.1; PostgreSQL и API не публикуются на хост.
На удалённом сервере используйте SSH-туннель:

```bash
ssh -L 8080:127.0.0.1:8080 user@server
```

Для публичного размещения сначала настройте HTTPS и корректный public origin;
простая смена bind на 0.0.0.0 не является подготовленным публичным развёртыванием.
Docker самостоятельно публикует порты, поэтому полагаться только на UFW нельзя.

API работает с ролью foxtube_api, worker — foxtube_worker; административный пароль БД
передаётся только PostgreSQL и одноразовой миграции. Права на новые таблицы
добавляются явно миграциями. Медиа доступны Nginx только для чтения.

## Учётные записи и API

Страницы: /register, /login, /account. Создаётся обычный пользователь и ровно один
канал с уникальным адресом вида @fox-…. Канал открывается через `/@handle`
(перенаправление на `/channels/{id}`). Email нормализуется; пароль — 12–128 символов.

| Маршрут | Назначение |
|---|---|
| GET /api/v1/auth/session | Текущая или новая анонимная сессия; user, csrf_token, expires_at |
| POST /api/v1/auth/register | JSON: email, password, display_name; создание аккаунта, 201 |
| POST /api/v1/auth/login | JSON: email, password; вход, 200 |
| POST /api/v1/auth/logout | JSON: {}; отзыв текущей авторизованной сессии, 200 |
| GET /api/v1/auth/me | Данные текущего пользователя; без входа 401 |

Для POST сначала получите /session с сохранением cookie, затем передайте
Origin, равный PUBLIC_ORIGIN, и X-CSRF-Token из ответа. После входа/регистрации/
выхода используйте новую cookie и csrf_token. Браузерные формы делают это сами.
В /docs нажмите Try it out у login/register и Execute: interceptor получает
CSRF автоматически; ручное заполнение Authorize не требуется. Swagger и страницы
используют общую cookie. Не публикуйте ответы /session и команды Swagger с токенами.

Повторный email даёт 409; неверный пароль или неизвестный email — одинаковый 401;
нарушение CSRF/Origin — 403; лишние поля или невалидный ввод — 422 без исходных
значений; превышение частоты — 429 с Retry-After. При заполненных слотах Argon2
или недоступности БД возвращается 503. Тело auth POST ограничено 16 КиБ.

## Каналы и взаимодействия

Канал показывает доступные зрителю видео и плейлисты автора, кнопку подписки
и управление собственными загрузками. `/subscriptions` — лента подписок и список
каналов; `/playlists` — создание своих плейлистов. Плейлист по умолчанию приватный.
На `/watch/{id}` доступны лайк, комментарии, сохранение и жалоба.

| Маршрут | Назначение |
|---|---|
| GET /api/v1/channels/{id}, /{id}/videos | Профиль без email и доступные видео автора |
| GET/PUT/DELETE /api/v1/channels/{id}/subscription | Состояние, подписка, отписка |
| GET /api/v1/channels/{id}/playlists | Доступные плейлисты автора |
| GET /api/v1/subscriptions, /subscriptions/channels | Доступная лента и подписанные каналы |
| GET /api/v1/videos/{id}/social | Счётчики и собственный лайк |
| PUT/DELETE /api/v1/videos/{id}/like | Идемпотентная установка/снятие лайка |
| GET/POST /api/v1/videos/{id}/comments | Пагинация/создание; JSON `{body}` |
| DELETE /api/v1/comments/{id} | Удаление автором комментария или владельцем видео |
| GET/POST /api/v1/playlists | Свои плейлисты / создание `{title, description, visibility}` |
| GET/PATCH/DELETE /api/v1/playlists/{id} | Просмотр / изменение / удаление владельцем |
| PUT/DELETE /api/v1/playlists/{id}/items/{video_id} | Добавление/удаление элемента владельцем |

Публичный плейлист не изменяет права видео. Его элементы и videos_count
вычисляются для текущего зрителя. Максимальная страница — 50 записей;
лайк/подписка/элемент не дублируются при повторе или конкурентных запросах.
Для мутаций необходимы cookie, точный Origin и CSRF; тело ограничено 16 КиБ.

## Модерация и первый администратор

После обычной регистрации своего аккаунта выполните на сервере:

```bash
docker compose run --rm --no-deps migrate python -m app.moderation.bootstrap --email your-existing-account@example.com
```

Это одноразовая операция с привилегиями миграций: существующий пользователь
становится первым admin, событие записывается в аудит. При наличии admin
повтор запрещён. Далее `/admin` — точный поиск email/ID, роли и журнал;
`/moderation` — открытые/закрытые жалобы, скрытие/восстановление и решения.
Понижение последнего администратора запрещено. Роли берутся из БД при каждом
запросе; повторный вход после смены роли не требуется. Подробные API и права:
[модерация](stages/moderation.md), [безопасность](security.md).

## Настоящее демо-наполнение

```bash
bash scripts/bootstrap.sh --demo
# Для уже запущенного проекта:
bash scripts/demo.sh
```

Команда создаёт 6 обычных аккаунтов, 12 шестисекундных MP4 со звуком, 6 комментариев,
6 плейлистов, подписки, лайки, два приватных доступа и жалобу. FFmpeg генерирует
исходники, затем API/Nginx и настоящий worker обрабатывают их до READY.
Файлы не зависят от внешних ссылок. Это демонстрационный видеосигнал,
не проверка всех реальных камерных форматов.

Случайные email/пароли и IDs сохраняются в `secrets/demo/manifest.json` (0600).
Пароли не печатаются; файл можно открыть локально для входа выбранным аккаунтом.
Не публикуйте его. Повтор сохраняет аккаунты, ролики и плейлисты; удалённые
вручную демо-комментарии не восстанавливаются. Отдельный flock запрещает два
одновременных наполнения. Демо не назначает администраторов и не очищает БД.
При FAILED команда прекращается с ошибкой: причину нужно проверить в студии,
после исправления удалить неисправный демо-ролик и повторить заполнение.

## Загрузка, просмотр и API видео

Страницы /upload и /studio требуют входа. Название и описание редактируются
на странице /watch/{id}; там же владелец управляет приватными разрешениями.
В ленту/поиск попадают только готовые видимые видео, доступные текущему зрителю.
В студии владелец видит также очередь, ошибки и незавершённые черновики.

| Маршрут | Назначение |
|---|---|
| POST /api/v1/videos | JSON title, description, visibility, expected_size; черновик и резерв, 201 |
| PUT /api/v1/videos/{id}/source | Сырые байты application/octet-stream, без multipart; принятие в очередь, 202 |
| GET /api/v1/videos и /mine | Доступная лента/поиск q либо собственные загрузки; page/page_size |
| GET/PATCH/DELETE /api/v1/videos/{id} | Карточка, изменение метаданных/доступа, логическое удаление |
| GET/POST /api/v1/videos/{id}/grants | Список разрешений; выдача по JSON email зарегистрированного пользователя |
| DELETE /api/v1/videos/{id}/grants/{user_id} | Отзыв разрешения |
| GET/HEAD /media/videos/{id}/playback и /poster | Проверка доступа и раздача через Nginx, включая Range |

Для всех изменений нужны текущие cookie, Origin и X-CSRF-Token как у auth.
В Swagger сначала выполните register/login, затем POST videos с фактическим
размером файла в байтах и PUT source с выбором этого файла. Бинарное тело
описано в OpenAPI. Опрос GET карточки показывает UPLOADING → QUEUED →
PROCESSING → READY/FAILED; READY содержит ссылки на доступные медиа.

Ограничения: MP4/MOV/WebM до 500 МиБ, 20 минут, 1920×1080 или 1080×1920,
60 fps. FFmpeg проверяет содержимое, включая контейнер и кодеки; расширение
не подтверждает пригодность. Выход H.264/yuv420p MP4 до 720p/30fps,
AAC при наличии аудио, faststart и JPEG. Отсутствие звука допустимо.

На пользователя — один зарезервированный черновик, одна активная передача,
5 ГиБ занятого/зарезервированного места. На сервер — две передачи и очередь
до 20 с учётом черновиков. Для результата резервируются 420 МиБ;
5 ГиБ свободного диска остаются неприкосновенными. Начать передачу нужно
за пять минут; передача ограничена 30 минутами. POST черновиков: до 10 попыток
на пользователя и 20 с IP за 15 минут. Превышение размера/квоты — 413,
недостаток места в хранилище — 507, занятый собственный черновик — 409,
очередь/активные передачи или частота — 429 с Retry-After. Частично
отправленный файл повторяется целиком; после 202
повторный PUT не создаёт задание и возвращает текущее состояние.

FFmpeg работает вне API, с арендой 120 секунд и максимум тремя попытками
при временном сбое. После жёсткого падения worker задание подхватывается
по истечении аренды. READY публикуется только текущей попыткой; privacy,
hidden и deleted не изменяются. Исходник удаляется после успеха, неудачный —
через сутки. Логическое удаление сразу запрещает новые запросы; физическое
выполняется worker. Ошибка удаления сохраняет учёт занимаемого места.

## Изолированные интеграционные проверки

```bash
bash scripts/test.sh
```

Скрипт строит development-образ, создаёт отдельный временный env и уникальный
compose-проект, затем запускает настоящие PostgreSQL, API, worker и Nginx.
Порт выбирается автоматически; запросы тестов идут через Nginx внутри тестовой сети.
После прогона удаляются только контейнеры, сети и тома этого тестового проекта.
Рабочий .env и рабочие тома не используются. Дополнительные аргументы передаются pytest:

```bash
bash scripts/test.sh -k readiness
```

Полный браузерный путь с настоящим H.264/AAC, загрузкой через экран,
обработкой, просмотром, перемоткой, социальными действиями и модерацией:

```bash
make test-browser
```

Создаётся отдельный одноразовый Compose-проект. Google Chrome for Testing
(amd64/arm64, версия и SHA-256 закреплены в Dockerfile.browser) и Playwright
устанавливаются только в тестовый образ. Браузер пользователя и его профиль
не меняются. Проверяются currentTime до и после перемотки, сохранение лайка,
комментария и плейлиста, подписка и её лента, жалоба, назначение роли в активной
сессии, скрытие/восстановление MP4/превью, закрытие жалобы, аудит и защита
последнего администратора. Администратор создаётся только в одноразовом
окружении через обычную регистрацию и привилегированную bootstrap-команду.
Также проверяются лента/поиск, 1440×900/390×844 и ошибки JavaScript. Отчёт и снимки остаются
в .artifacts/video-browser; cookies, пароли и трассы запросов туда не пишутся.
После прогона удаляются только тестовые контейнеры и тома.

Без Docker интеграционные проверки не заменяются SQLite или фиктивным успешным
результатом. Состояние проверок на текущей машине фиксируется отдельно в
[status.md](status.md). Успешный Docker-прогон на macOS не доказывает установку на
чистую Ubuntu: её нужно проверить в отдельной чистой виртуальной машине.

Установка Docker основана на [официальной инструкции Ubuntu](https://docs.docker.com/engine/install/ubuntu/).
Конфигурация сервисов следует [Compose Specification](https://docs.docker.com/reference/compose-file/services/).
